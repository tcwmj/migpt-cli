# ADR-002: JSON 文件存储（不引入 SQLite）

## 状态

已采纳（2026-10）

## 背景

需要选择数据持久化方案。候选方案包括 SQLite 和 JSON 文件。

## 决策

使用 JSON 文件存储（`~/.migptgui/` 目录），不引入 SQLite。

## 理由

1. **数据规模极小**：运行时数据合计约 21 KB（含 7.4 KB 内置型号种子），真实用户数据 < 2 KB
2. **访问模式简单**：单用户本地面板、低频写、全量读，现有 `readJson` 缓存 + 原子写 + 写队列已够用
3. **运维友好**：数据目录为可读 JSON，用户可直接查看和编辑，便于自助排查与备份
4. **依赖轻量**：SQLite 需要原生依赖，跨平台/多架构 Docker 镜像复杂化
5. **痛点已有方案**：真实痛点在 schema 校验（zod）与数据迁移（版本化迁移框架），JSON + zod 即可覆盖

## 技术实现

- **原子写**：随机临时文件名 + `rename`，防止断电损坏
- **写串行化**：Promise 队列，防止并发写入导致数据丢失
- **读缓存**：按文件 `mtime`/`size` 校验，命中即免去重复读盘
- **Schema 校验**：zod 在落盘前把关（写入校验失败抛 `DataValidationError`），读取时逐条过滤脏数据
- **数据迁移**：版本化迁移框架（当前 `DATA_VERSION=2`），启动时按版本逐条执行幂等迁移

## 复评触发条件

- 记录量级上万
- 需跨实体事务/复杂查询/全文检索
- 多用户并发写

## 后果

- 正面：零原生依赖，Docker 镜像轻量
- 正面：数据目录可读，用户可直接排查
- 正面：备份/恢复简单（JSON 导出/导入）
- 负面：无 SQL 查询能力，复杂过滤需在应用层实现
- 负面：全量读取，数据量大时性能下降（当前规模无此问题）
