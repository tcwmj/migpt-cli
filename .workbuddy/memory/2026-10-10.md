## 本地前端开发自动刷新（livereload）

- 痛点：改前端后必须手动 WIN+CTRL+R 硬刷新。根因有两点：
  1. `scripts/dev.js` 用 `webpack --watch` 只重编译，**不通知浏览器刷新**（没有 HMR/livereload 触发机制）。
  2. 后端 `packages/server/src/index.ts` 用 `express.static(staticPath,{maxAge:'1h',etag:true})` 托管 GUI，浏览器 1h 内软刷新命中缓存，硬刷新才绕开。
- 方案（保留现有 `webpack --watch` + 后端托管 36597 架构，最小侵入）：
  1. 新增 devDependency `webpack-livereload-plugin@3.0.2`（peer: webpack ^4||^5，兼容当前 5.95）。
  2. `packages/gui/build/buildWebpackConfig.js`：仅 `mode==='development'` 时 `base.plugins.push(new LiveReloadPlugin({port:35729, appendScriptTag:true}))`。注入方式：webpack5 走 `JavascriptModulesPlugin.renderRequire` 钩子，把 livereload 客户端塞进 `main.js` 运行时（`_autoloadJs` 用 `location.hostname` 解析地址，自动适配 127.0.0.1 / localhost 打开）；脚本地址 `//<页面hostname>:35729/livereload.js`。**注意**：单次 `webpack` 构建（非 watch）不注入，因 livereload 服务在 `watchRun` 钩子才启动，`_scriptTag` 注入依赖 `_isRunning()`；只有 `webpack --watch` 才注入（dev.js 正是 watch 模式，正确）。
  3. `packages/server/src/index.ts`：`isDev = MIGPT_DEV==='1' || NODE_ENV!=='production'` 时对 GUI 静态资源 `setHeaders` 设 `Cache-Control: no-cache`，关掉强缓存，确保 livereload 软刷新拉到最新 bundle（prod 仍 1h）。
  4. `scripts/dev.js`：spawn 后端时 `env:{...process.env, MIGPT_DEV:'1'}`。
- 验证：watch 模式产物 `dist/main.js` 含 `webpack-livereload-plugin-script-...` 与 `[Live Reload] enabled`；服务端 tsc 无新增错误。
- 效果：`npm run dev` 后改前端代码 → webpack 重编译 → 已打开页面自动刷新，无需手动刷新。
- 边界：livereload 服务端口 35729；若 dev 重启后端口被旧 webpack 残留占用，插件会优雅降级（日志 "Live Reload disabled: EADDRINUSE"）而非崩溃，仅失去自动刷新。从其他设备经 LAN IP 访问 GUI 时 livereload 回连的是该设备的 localhost，故自动刷新仅限开发机本机浏览器。

## 修复：livereload 自动刷新仍失效（CSP 拦截根因）

- 现象：已加 livereload 但改前端仍需手动 WIN+CTRL+R，自动刷新不生效。
- **真正根因**：`packages/server/src/index.ts` 的 helmet **CSP** 把 `script-src`/`connect-src` 都限定为 `'self'`（仅 36597 同源）。而 livereload 客户端要从**独立端口 35729** 用 `<script src="//<页面hostname>:35729/livereload.js">` 加载脚本、并以 `ws://<host>:35729` 回连——两者都是**跨端口来源**，被 CSP 直接拦截。注入虽成功（main.js 里确有 `webpack-livereload-plugin-script-...`），但客户端脚本加载/ws 连接被浏览器拦，页面不刷新。
- **修复**（`packages/server/src/index.ts`，仅此一文件）：
  1. 把 `isDev`（MIGPT_DEV==='1' || NODE_ENV!=='production'）判定提到 helmet 之前，统一复用（原 static 块里的重复定义删除）。
  2. dev 时 `script-src` 追加 `http://localhost:35729 http://127.0.0.1:35729`，`connect-src` 追加 `ws://localhost:35729 ws://127.0.0.1:35729`（端口可用 `MIGPT_LIVERELOAD_PORT` 覆盖）；prod 下数组为空，CSP 保持 `'self'` 收紧。
- **验证（端到端，均通过）**：
  - 临时 createApp 实例抓头：dev 下 CSP 含 35729 的 http+ws 白名单，`Cache-Control: no-cache`。
  - 运行中的 36597 实测响应头同样放宽；`main.js` 确认含 livereload 客户端。
  - 手工构造 WebSocket 客户端连 `ws://127.0.0.1:35729/livereload` → 升级 101，收到 tiny-lr hello；touch 前端源文件触发重编译后**持续收到 reload 广播**（E2E_EXIT:0）。
- 结论：CSP 放行 + 关缓存 + 脚本注入 三者齐备后，`npm run dev` 改前端代码即自动刷新，无需手动刷新。
- 注意：CSP 是上一轮 livereload 改动被"看起来没生效"的真正拦路石——只加插件与关缓存不够，跨端口来源必须同时写进 CSP。

## dist 陈旧 ReferenceError 排障（asyncHandler is not defined）

- 现象：用户跑 dev 报 `accounts.js:43 asyncHandler is not defined`。根因非源码（源码 import 完好），而是 **packages/server/dist 编译产物过期**：批量包裹脚本分两步（先包调用后补 import），中间态被 watcher 编译进 dist（dist 14:07 < src 14:08），之后未再触发重编译；dev-server.mjs 直接加载 dist 即报错。
